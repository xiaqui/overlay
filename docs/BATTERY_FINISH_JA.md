# 電池表示の最終仕上げ

## 保存と幾何

新しいbattery_directionは0=横右、1=横左、2=縦上。未保存時は旧battery_reversedを読む。明示選択時には旧キーも更新し、新キーを優先。初期化時に旧size/x/yをbattery_size/base_x/base_y/anchor_sizeへ一度だけ保存し、元キーは残す。新キーがあれば上書きしない。

電池サイズ10〜40sp（OS fontScaleは一回）、縦横比60〜160%は長辺補正。100%は旧本体0.94:0.56。縦型は同じ幾何を90度回転し、端子が上、残量は下から上。線幅・内側余白は短辺/長辺で安全に上限を設ける。端子・残量・boltも同じ座標変換を使う。

電池X/Yは旧配置からの−64〜100dp補正。正のXは右端から内側、正のYは下。右時計の位置・寸法は電池の調整で変えない。旧条件のままなら従来の結合窓を維持し、左時計または独立調整時だけ最大2個の最小非タッチ窓。大きな電池や極端な位置は重なり/画面外を許す手動調整であり、自動衝突回避はしない。設定の「初期値に戻す」でサイズは移行時の旧値、比率100%、位置補正0へ復帰し、向きと時計設定は変えない。

## 影

時計の描画・影値は変更なし（blur0.55dp、dx0.55dp、dy0.65dp、alphaB8）。電池の本体と端子を合わせたPathへ同じsetShadowLayerを使い、外側のみclipして柔らかい影を描く。空き容量は内側のalpha70黒で独立にコントラストを確保。端子は前面色、boltは明色キーライン＋濃灰塗り。旧い硬い全体シルエットは廃止。

描画更新は既存の電池イベント・分境界・画面更新のみ。新規poll/Service/権限/ライブラリ/ネットワークなし、Bitmapキャッシュなし。小窓と既存SOFTWARE layerを利用する。

## 自動試験と実機検収

純Kotlinで各方向の変換・端点・余白・残量割合を検証。Android描画で全方向×サイズ10/14/40×比率60/100/160×fontScale1/1.5×白黒×0/20/50/80/100/不明/充電を検査。時計ピクセルの不変、設定移行/優先/保存/復帰を確認する。API24は電池試験限定（既存全体suite終了ハングのため）。成功/失敗はWORK_PROGRESSに実績を記録する。

Z3TC(6)/Z4T(7)/XZ1C(8)/Mini(9)/Hand(10)で旧版から更新し、旧向き・サイズ・位置が保持されること、全方向、両端サイズ/比率、負数、時計左右/個別OFF、電池のみ例外、白黒・残量・不明・充電、回転・OS特大文字、消灯復帰・権限取消、タッチ透過を確認する。特に端子の白い形・未充填部分・boltを比較する。添付画像は比較参考のみでコミットしない。自動描画合格は純正一致/実機合格ではない。極端値から初期値復帰して外観を戻せること。
