## 4. 最大の未解決事項：Z3TC の上下バー色不一致

社長が提示した写真は **Xperia Z3 Tablet Compact（Z3TC、Android 6.0.1）** のもの。Z4 Tablet（Android 7）ではない。Chrome と NoRoot Firewall の複数アプリで、上のステータスバーと下のナビゲーションバーの見た目の色が違う。Chrome のアプリ別固定色 `#FFFFFF`、上下同色 ON が主要な再現設定。これが **最新版0.9.0実機でどうなるかは未確認**。

ソースと自動テストでは同じ `tint.color` / `#FFFFFFFF` が上下 Spec に渡り、固定色は暗色化されない。Android 6/7 の上部ウィンドウは TYPE_PHONE（2002）、下部は通常 TYPE_SYSTEM_OVERLAY（2006）。この違いが原因とはまだ断定できない。上部 `StatusbarLayer` の条件不成立、配置失敗、描画成功だが SystemUI に隠れる、の各可能性を区別する必要がある。

今回の 0.9.0 では **表示方式を恒久変更していない**。診断を詳細画面へ追加し、アプリから Overlay 画面へ戻った時も、直前の外部アプリのスナップショットを保持できるようにした。出力には対象 package・取得時刻・上下期待色・色ソース・ウィンドウ type・要求/実座標とサイズ・ready/draws・バー状態・非適用理由が含まれる。ただし ready=true / draws>0 は見た目の可視性の証明ではない。

### 次の実機確認（最優先）

1. Z3TC に配送された 0.9.0 を**既存アプリへ上書き更新**。旧時計・電池サイズ、位置、比率、向き、個別固定色などが保持されることを確認。アンインストールは保存値を消すので避ける。
2. Overlay のナビバー着色 ON / 「上部バーにも同じ色を適用」ON、Chrome 固定色 `#FFFFFF` で Chrome を表示。上下の実際の色と OS時計/通知アイコン/ナビボタンの視認性を確認する。
3. Overlay → **詳細設定／マニュアル → 現在の診断**を開き、採取対象が Chrome の package であること、採取時刻、上/下期待 ARGB、type、座標、ready/draws、非適用理由を確認。**この診断表示のスクリーンショットが次の原因究明の鍵**。個人情報が写っていれば共有前に伏せる。
4. 同様に NoRoot Firewall でも確認。必要なら Overlay 自身との違いを比較。
5. 2段階の白/黒プレビュー、時計・電池の「なし」復帰、角丸 OFF 時半径表示、権限往復、回転、タッチ透過、アプリ別固定色編集/キャンセルを確認。
6. Android 7〜10 の各実機は別途検収。Z3TCの現象を他 OS で再現済みと扱わない。

## 5. 性能・容量の判断と今後

- **容量は +5,086 bytes（約 0.75%）** なので、今回の変更による配布サイズ増は実用上軽微。
- 新規 Service・タイマー・poll・権限・通信・永続ログはない。既存のバー観測の反復内で Layer geometry・診断 state・権限を収集する処理は追加されたため、**CPU/PSS/電池の増分は未実測**。エミュレータ CI 成功を消費電力の検収と呼ばない。
- 社長の方針：**原因調査中は診断を残す。上下同色問題が実機で解決したら診断機能を外す。** 今から原因究明を犠牲にして複雑な診断最適化をする必要はない。撤去時は診断専用収集・一時保存・UIを整理し、必要な本修正と通常機能は残す。
- 上部ウィンドウの type を根拠なく 2006 に変えない。OS時計・通知アイコン、ナビボタン、タッチ透過を損なわないことを条件とする。
- 定常負荷を厳密に比較するなら、0.8.0 と 0.9.0 の同機種・同条件・同測定時間で PSS/CPU/電池を比較。現時点で負荷実測値の比較はない。
